# Результаты ДЗ №1 «Освоение векторизации», вариант 3 (C = A+B, D = A−B)

Файл сгенерирован `scripts/report_table.py` из `results/raw.csv`. Руками не править.

- Тип данных: `float` (4 Б/элем.); конфигураций: 378; прогонов на конфигурацию: 11.
- Основная цифра — **минимум** из прогонов (§6.2.3 ТЗ); рядом медиана, σ (в % от минимума) и разброс `спред = (max−min)/min`.
- Конфигурации с разбросом > 5 % помечены `*` — по §6.2.3 прогон считается зашумлённым и его следует повторить.
- Пиковая ПСП: **измерено (bandwidth.csv), по минимальному времени: Peak_BW = 57.95 ГиБ/с = 62.2 ГБ/с; кандидаты: add_nt 57.95 ГиБ/с (уже без RFO); add 76.38→57.28 ГиБ/с (пересчёт 16→12 Б/элем., без RFO)**.
- FLOP на прогон = `2·N²` (считаются обе матрицы C и D в обоих режимах); трафик = `bytes_per_elem · 2·N²`, ГиБ/с считаются по фактическому трафику (§6.4.1). `bytes_per_elem` берётся из CSV как есть.
- Режимы: `sep` — два раздельных прохода, `fused` — один слитый проход; в обоих случаях считаются обе матрицы, времена сравнимы напрямую.
- Модель трафика единая для всех этапов: **12 Б/вых. элем. для `sep` и 8 для `fused`**, независимо от NT-store. На M4 обычный store не платит за write-allocate/RFO, а `stnp` не даёт выигрыша, поэтому старая модель ТЗ (16 / 12 Б с RFO) не применяется.
